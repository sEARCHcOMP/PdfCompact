# PDF→DXF 変換(図面変換タブ)実装仕様 — 設計確定 2026-09-19

設計=Fable で確定済み。**実装は 🟢Opus で進めてよい**。ただし末尾「実機検証ゲート」を通るまで配布しない。

## 0. 目的と前提
- CAD出力のベクタPDFを、Jw_cad で開ける DXF に変換する。**用途は寸法・面積を測る根拠**(ユーザー決定)。
- 置き場所は PDF Compact の新タブ。ブラウザ完結・ファイルは外に出ない。
- JWW直接出力はやらない(バイナリ書込=高リスク。DXFで不足が出たら別途検討)。
- テストは自作PDFのみ。実物件の図面は使わない(CLAUDE.md 掟1)。

## 1. Jw_cad 実機で確定した事実(2026-09-19 ユーザー実機、推測ではない)
| 項目 | 結果 |
|---|---|
| 単位 | DXF座標を**実寸mm**で書けば、Jw_cadの測定で同じ値が出る(3640→3,640) |
| 文字コード | **Shift-JIS(CP932)**で日本語が化けない。形式は R12($ACADVER=AC1009) |
| 線種 | **TABLES に LTYPE 表と LAYER 表が無いと全部「補助線種」になる**(印刷されない線。最重要の回帰ポイント)。表があれば、線ごとに 6/62 を明示しても BYLAYER でも実線になる |
| 破線・鎖線 | LTYPE の DASHED→破線、CENTER→一点鎖線として入る |
| 色 | ACI 1赤 2黄 3緑 4水 5青 6紫 がそのまま通る |
| 円 | CIRCLE は円として入る。中心は右クリックでは読めず、クロックメニュー「中心点・A点」で取る(円データでないと効かないので CIRCLE/ARC 出力に意味がある) |
| 検証済みエンティティ | LINE / CIRCLE / TEXT のみ。**ARC と POLYLINE は未検証**(→実機検証ゲート) |

実績のある書式(標本2)の要点: HEADER($ACADVER) → TABLES(LTYPE: CONTINUOUS/DASHED/CENTER、LAYER: 使う全レイヤを 62=7, 6=CONTINUOUS で定義) → ENTITIES → EOF。改行CRLF。
LTYPE 書式: `0 LTYPE / 2 名前 / 70 0 / 3 説明 / 72 65 / 73 要素数 / 40 全長 / 49 各要素`。

## 2. 構成(影響最小化)

## 3. 抽出器(pdf.js getOperatorList)
追跡する状態(save/restore で退避): CTM、線色、破線(setDash)、線幅。
- `paintFormXObjectBegin`(matrix) は save+transform、End は restore(既存実装はここを見ておらず位置がズレる)。
- `constructPath` は**直後の描画命令で採否を決める**: stroke / closeStroke / fillStroke / eoFillStroke / closeFillStroke 系のみ出力。**fill のみ・clip・endPath は捨てる**(ハッチの塗り、アウトライン化文字、切り抜き枠が線になるのを防ぐ)。
- moveTo/lineTo/closePath(始点へ閉じる)/rectangle(4辺のLINE)/curveTo系。短い線も捨てない。
- 曲線: 連続ベジェが同一円に乗る(制御点が κ≈0.5523 の関係、等方スケール)なら **CIRCLE(全周)/ARC(部分)**。それ以外は折れ線化(弦誤差=紙上0.05mm以下)。
- 座標系: `page.getViewport({scale:1})` の変換で回転(/Rotate)とCropBoxを吸収 → Y を反転して DXF の上向きYへ。画面表示と同じ向きになること。
- pdf.js 3.11.174 の色命令の引数形式(0-255か0-1か)は実装時に実測して確定すること。

## 4. 縮尺(測定用途の要)
- **主役は「既知寸法の2点指定」**: キャンバス上で2点クリック(抽出した端点へスナップ)→ 実寸mm入力 → 係数 k[mm/pt] = 実寸 / 2点間pt。「用紙に合わせて印刷」で 97% 等に縮んだPDFの一律ズレをこれで消す。
- 補助: 縮尺プルダウン(1/20,1/50,1/100,1/200…)。k = 25.4/72 × 分母。
- **検算表示**: 縮尺確定後、別の2点をクリックすると実寸を表示(図面の寸法文字と突き合わせられる)。
- 未確定のまま出力させない(ボタン無効+理由表示)。

## 5. 精度表示
- 変換前の座標値から丸め幅を推定: 候補 {72/300, 72/600, 72/1200, 72/2400, 0.01, 0.001}pt のうち、座標の99%以上が倍数に乗る最大の幅。該当なしは「0.001pt未満」。
- 縮尺確定後に「この図面の精度: 実寸で約±○mm」を常時表示(±幅/2×k)。取説にも「プリンタ経由PDFは1/100で数mmずれ得る」と明記。

## 6. 文字
- `getTextContent` → TEXT(位置・高さ=フォントサイズ×k・回転角)。アウトライン化された文字は線にもTEXTにもならない(fill のため)旨を取説に書く。
- Shift-JIS 変換は**外部ライブラリ不要**: `new TextDecoder('shift_jis')` で全2バイト符号を1回デコードして逆引き表を作る(オフラインで動く)。変換不能文字は `?` に置換し件数を画面に出す(無言にしない)。
- 出力は Blob(バイト列)。文字列のままダウンロードさせない(UTF-8になって化ける)。

## 7. マッピング
- 線種: setDash 空→CONTINUOUS / 要素2→DASHED / 要素4以上→CENTER。
- 色: RGB を ACI 1〜6 の最近傍へ。黒・白・灰は 7。
- レイヤ: SEN(線) / EN(円・円弧) / MOJI(文字)。線幅は捨てる。
- ファイル名: `DXF変換_{YYYYMMDD}_{連番}.dxf`。複数ページは1ページ1ファイル、複数選択時は ZIP(既存 JSZip)。

## 8. 断るケース(必ず理由を画面に残す)
- 線が0本で画像があるPDF → 「スキャン画像のため線を取り出せません」。
- パスワード必須PDF → 既存文言に合わせて案内。編集ロックのみのPDFは pdf.js で読めるのでそのまま変換可(pdf-lib を通さない)。

## 9. 自動テスト(tests/pdf2dxf.spec.js、PDFは pdf-lib でページ内生成)
1. 3640×2730 の四角(1/100)→ LINE 座標が±0.5mm以内
2. 97%縮小PDF を2点指定で校正 → 実寸が復元される
3. 円 → CIRCLE(中心・半径)、半円 → ARC
4. 破線 → 6=DASHED
5. **TABLES に LTYPE と LAYER が必ず在る**(補助線化の回帰番犬)+日本語が CP932 バイトで入っている
6. fill のみの図形・clip パスが出力されない
7. 画像のみPDF → 断りメッセージ
8. /Rotate 90 のページが見た目どおりの向き
9. 縮尺未確定では出力ボタン無効

## 10. 実機検証ゲート(配布前に必須・ユーザーのJw_cadで)
- 実装した変換器が**実際に吐いたDXF**(自作PDF由来: 直線・円・円弧・破線・日本語・折れ線化曲線を含む)をユーザーに開いてもらい、①測定値 ②ARCが円弧で入るか ③折れ線化曲線の見え方 ④補助線になっていないか を確認。
- ARC が通らなければ折れ線(LINE列)に落とす。POLYLINE は使わず LINE 列で出すのが安全側(LINE は検証済み)。
