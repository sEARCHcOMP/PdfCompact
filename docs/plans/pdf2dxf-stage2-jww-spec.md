# 図面変換 第2段の仕様 — JWW書き出しと DXF 入力

状態: **実装済み(2026-09-21、PDF出力ぶん)**。方針は利用者承認済み(2026-09-20)。残っているのは **DXF を入力にする道**(メーカー提供のDXFを開いて JWW/DXF にする)で、これは第3段とする。

## なぜ要るか(実機で確定した事実)
- Jw_cad は DXF の色を必ず「SXF対応拡張線色」(原色)で読む。標準の線色1〜8で読ませる設定は無い(V5.00e 以降の仕様)。利用者の線色設定(白背景用に調整した色)にも、線色ごとの印刷線幅にも乗らない。
- JWW を直接書けば、1本ずつ線色番号・線種番号を指定できる。手元の Python 版(prims2jww)で実証し、Jw_cad 8.25a で合格。
- メーカー提供の DXF は SPLINE・ELLIPSE 等で Jw_cad では外形が欠ける。手元の Node 版(dxf2jww)で分解できる(実証済み)。
- どちらもこのPCの Python / Node に依存していて他人に渡せない。PDF Compact(単一HTML・自動更新・全員が持っている)に入れるのが理想。

## 利用者の決定(2026-09-20)
1. ひな形: **内蔵の標準ひな形 + 各自の登録で上書き**。
2. 色の割り当て: **2種類から選べる**(白背景用 / 元の色に近い線色)。選択は覚えておく。
3. 自作標本のヘッダを公開リポに入れてよい(内蔵ひな形用)。個人情報が無いことは確認済み(文字列は SXF の標準色名・線種名と空のメモだけ)。

## 機能
- 入力: PDF(今までどおり)または **DXF**(新規。拡張子 .dxf)。DXF は実寸なので縮尺合わせの手順は出さない。
- 出力形式: **JWW(おすすめ)** / DXF。選択は覚えておく。
- JWW の中身:
  - 座標は図寸mm・用紙中央が原点。PDF 由来は 用紙上のmm(pt × 25.4/72 × UserUnit)をそのまま使い、縮尺は合わせた分母(標準縮尺を採用していればその値。測った値の時は小数のまま)。DXF 由来は実寸 ÷ 縮尺分母(自動選択: 1,2,5,10,20,30,50,100,200… のうち A3 に余白10mmで収まる最小。図枠つきは余白3mmまで可)。
  - 用紙: PDF 由来はページの大きさに合う Jw_cad の用紙(A4〜A0。合わない時は一回り大きい用紙)。DXF 由来は A3。
  - 線色・線種: 対応表(下)。線幅0(線色ごとの設定に従う)。文字は常に線色2。塗りは線色番号の色。補助線色・補助線種・SXF色は使わない。
  - レイヤ: 由来のレイヤ名を出てきた順にグループ0のレイヤ0〜Fへ(あふれたらグループ1へ)。PDF 由来は 線=「線」、円・円弧=「円」、文字=「文字」の3レイヤ。
  - 掃除: 図寸でふくらみ 0.001mm 未満の円弧は線に。長さ0の線・半径0の円弧・空の文字・高さ0の文字は捨てて件数を画面に出す。
- 対応表(1か所にまとめる):
  - 白背景用(既定): 赤→線色8、青→6、紫→7、橙→4、黒→2、灰→5。見えにくい色(黄・緑・水色)は 実線→2、破線・鎖線・点線→5。
  - 元の色に近い線色: 赤→8、黄→4、緑→3、水色→1、青→6、紫→7、橙→4、黒(白)→2、灰→5。
  - 線種: 実線→1、点線→2、破線→3、一点鎖線→5、二点鎖線→7。
- ひな形:
  - 内蔵: 自作標本のヘッダ(レイヤ名は空にする)。
  - 登録: 利用者が自分の Jw_cad で保存した .jww を1回選ぶ。**ヘッダ部分だけ**を取り出してブラウザの中(IndexedDB)に保存する(図形は保存しない・外に送らない)。Ver700 以外・読めないファイルは理由を表示して断る。登録の解除もできる。
  - 内蔵で書き出した時は、保存後の文言に「標準のひな形で書き出しました。線の色や印刷の設定をご自分の Jw_cad に合わせたい時は、ひな形を登録してください」を添える。
- 書いた JWW は、書き出す前に必ず読み直して検査する(読み残し0・件数一致・線色1〜8・線種1〜8・範囲が用紙内)。1つでも外れたら保存せず理由を表示。

## 作り(PDF Compact の決まりに合わせる)
- `src/app/71-dxf-flatten.js`: DXF → 部品(線・円弧・円・文字・塗り・点)。`dxf2jww.js` の中身を、ブラウザで動く純粋な関数にして移した(fs・Buffer を使わない)。**入っているが、まだ画面からは呼んでいない**(第3段で DXF 入力に使う)。
- `src/app/74-jww-template.js`: 内蔵ひな形(自作標本のヘッダ 14,472 バイト)を base64 で持つ。
- `src/app/70-pdf2dxf.js` の「3.6 JWW の書き出し」: 図面 → 部品・用紙の選定・ひな形の出し入れ(IndexedDB)・保存後の文。
- `src/app/72-jww-writer.js`: ひな形ヘッダの解読(`header_layout` の移植)・図形の書き込み(MFC CArchive 形式: クラスタグ、件数の 0xFFFF エスケープ、ANSI/Unicode の2つの文字列形式)・ひな形の取り出し。
- `src/app/73-prims-to-jww.js`: 対応表・掃除・縮尺と用紙・レイヤ割り当て・読み直し検査。
- 正しさの担保: **同じ入力に対して手元の Python 版と1バイトも違わない**ことを 手元の答え合わせスクリプト run-checks.js で確かめる(Python を都度呼んで全数で突き合わせる。52件中51件がバイト一致、残り1件は Python 版が読めないファイルを作る入力なので対象外)。このリポジトリのテスト(`tests/pdf2dxf.spec.js`)は、画面から出した JWW を読み直して線色・線種・レイヤ・用紙・縮尺を確かめる。

## 実装で変えたこと(2026-09-21)
- `choosePaperCode` は**幅と高さを入れ替えない**。Jw_cad の用紙は横置きしか無く、図面はページの向きのまま置くので、入れ替えると A4縦(210×297)に A4(297×210)を選んでしまい、図形が用紙の上下からはみ出して読み直し検査で必ず止まっていた。縦向きのページは一回り大きい用紙になる(A4縦→A3、A3縦→A2)。
- 用紙を選ぶ時、図形の側に 1mm の余裕を見る。用紙選びは 0.5mm まで大目に見る(1191pt = 420.16mm のような、A3 を少しはみ出す大きさのページを A3 に収めるため)ので、その分だけ図形がはみ出すと検査で止まるため。
- ヘッダに書く縮尺の分母は、標準の縮尺を採用した時・プルダウンで選んだ時は**その値ちょうど**を書く(`pg.k` から割り戻すと 99.99999999999999 になり、Jw_cad の縮尺の欄に出てしまう)。
- 逆スラッシュの表記を書かない・script の終了タグの文字列を書かない・CRLF・`node build.js`・全テスト合格、はこれまでどおり。
