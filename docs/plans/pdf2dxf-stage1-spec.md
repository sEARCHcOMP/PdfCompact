## A. 精度のモデル(いちばん大事)

誤差は2種類。(a) 縮尺の誤差 = 長さに比例。(b) 測る線の両端の丸め = 長さに無関係の床。(a) をゼロに近づけ、(b) は正直に見せる。

### A1. 座標の刻み q の推定を直す(`estimateQuantum`)
- 刻みの判定に使う差分は **直線(L)の端点だけ** にする。曲線(C)の端点は格子に乗らないPDFがあり(Chromium製)、細かいPDFなのに「推定できません」になっていた。直線の差分が20個未満の時だけ、曲線も含めた従来の差分に戻す。
- 返り値に `minDiff`(0でない差分の最小値、pt)を足す。
- 候補の倍数(400dpi = 0.18pt = 0.06pt の3倍 など)を探すのは、dpi の候補と小数の pt の候補だけ。**mm の格子の候補(用紙上 0.1mm・0.01mm)は倍数へ広げない**。5mm・10mm の切りのよい寸法で設計した図面は、線の位置が用紙上 0.05mm・0.1mm の倍数に揃うが、これは設計の寸法の揃い方であって、記録の丸めの刻みではない(広げていた時は、細かいCADのPDFを「実寸で約 20mm きざみ」と言っていた)。1/100 で実寸 10mm の倍数に揃った図面の q は用紙上 0.1mm まで、実寸 5mm の倍数なら用紙上 0.01mm。
- 表示の分類(k = mm/pt、g = q×k = 1目盛りの実寸mm)。画面の文では「1目盛り」と言わない(現場の人に通じない。G の I4):
  - q が取れて g ≥ 0.05mm: 「このPDFは、線の位置が実寸で約 g mm きざみに記録されています(測った長さは最大 ±g mm ずれます。斜めの線では約1.4倍)」
  - q が取れて g < 0.05mm、または q が取れず `minDiff × k < 0.05mm`: 「線の位置は十分に細かく記録されたPDFです(実寸で 0.05mm 未満のきざみ)」
  - それ以外(q が取れず minDiff も粗い): 「座標の細かさを推定できませんでした。寸法文字と突き合わせて確かめてください」(注意色)
  - 直線の差分が足りない: 従来どおり「線が少ないため計算できません…」
- 以後、q が取れない時の計算上の q は `min(minDiff, 0.001)` ではなく **0** として扱う(床0・判定の許容は下限値が効く)。ただし上の3番目の分類の時は、標準縮尺の自動採用をしない(A2)。

### A2. 標準縮尺の確認・採用(ルールR)
寸法2点で合わせた時(`applyDim`)に、測った縮尺が標準縮尺と「測り方の誤差の範囲で」一致したら、**標準値ちょうど**を採用する(縮尺の誤差がゼロになり、長さに比例する誤差が消える)。
- 標準縮尺の分母: 縮尺プルダウン(#p2dPreset)の選択肢と同じ集合を使う。
- 測った分母 den = k ÷ (PT2MM × UserUnit)。最も近い標準分母 N。rel = |den/N − 1|。
- u = q ÷ d(d = 合わせた2点間の距離 pt)。吸着していない点が1つでもあれば u = max(u, (1/ds) ÷ d)(画面1ピクセルぶん)。
- 判定:
  1. u > 0.0015 → 採用しない。「寸法が短いため、標準の縮尺かどうか判定できません。もっと長い寸法で合わせると、誤差が小さくなります」
  2. rel ≤ max(1.5u, 0.0003) → 採用。k = PT2MM × UserUnit × N。表示「縮尺: 1/N(寸法 ○mm で確認。標準の縮尺ちょうどを採用)」
  3. それ以外 → 測った値のまま。「縮尺: 約 1/103.1(測った値。原寸で出力されたPDFではないようです)」
- A1 の「推定できませんでした」分類の時は 2 をしない(測った値のまま+注意)。
- 採用した時は、測った値に戻すリンクボタンを出す(「測った値(約 1/100.1)を使う」)。戻した後は「標準の縮尺(1/100)を使う」で再採用できる。
- ページごとに `pg.cal = { d, real, snapped, u, denMeasured, nominal, adopted }` を持つ。プルダウンで選んだ時は `pg.cal = { preset:true, nominal:N }`。
- 「同じ用紙サイズのページに使う」で写す時は cal も写す(kFrom はそのまま)。

### A3. 長い寸法への誘導
- 寸法で合わせるモードの説明文に「図面の中で**いちばん長い寸法**(建物の端から端など)を使うと、誤差が小さくなります」を足す。
- 2点を取った時点で、**縮尺の精度が実際に落ちる時だけ**、その場に「短い寸法です。図面にもっと長い寸法があれば、そちらで合わせると誤差が小さくなります(このままでも合わせられます)。」(注意色、確定は止めない)。条件:
  - 線の位置のきざみ q が分かるPDF: u = q ÷ d > 0.0005(0.05%)。600dpi・1/100 なら、用紙上 240pt(実寸 約 8.5m)より短い寸法。
  - q が分からないPDF: d が用紙の長辺の 15% 未満。
  - (2026-09-21 改定。以前は一律に「用紙の長辺の 25% 未満」で、細かく記録されたPDFや、これ以上長い寸法の無い図面でも出ていた。)

### A4. 確かめる(検算)を強くする
- 別の2点をクリックすると「この2点の実寸: 2,730mm(誤差の目安 ±3mm)」。
- 誤差の目安 = 端点の床 + 長さ×縮尺の相対誤差。
  - 端点の床 = q × k ×(|cosθ| + |sinθ|)(θ は測った線の向き。軸に平行なら q×k)。吸着していない点があれば、画面1ピクセルぶん(k ÷ ds)を点ごとに足す。
  - 縮尺の相対誤差 = 標準縮尺を採用中・プルダウン選択なら 0、測った値なら cal.u。
  - 0.5mm 未満は「±1mm未満」と出す。
- 任意入力「図面に書いてある寸法(mm)」を足す。入れた時:
  - |実寸 − 入力| ≤ 誤差の目安 + 0.5 → 「図面の寸法と一致しました(差 ○mm)」(成功色)
  - 外れ → 「図面の寸法と ○mm 合いません。縮尺が違うか、用紙に合わせて縮小されたPDFの可能性があります」(注意色)+ボタン「この寸法で合わせ直す」(その2点と入力値で A2 をやり直す)。
  - **判定を出すのは、入力が止まってから(約 0.6 秒)・Enter・欄を離れた時**。入力している間は判定の行と合わせ直しのボタンを隠し、縮尺の欄の高さを保つ(1文字ごとに判定していた時は、「3640」の途中の「3」「36」「364」で「合いません」とボタンが出ては消え、欄の高さが 96px 跳ねた)。
  - 成功の色(緑)は「一致しました」の判定だけ。実寸の行はふつうの文字色、合わない時は図面の上のラベルも注意色(合わないのに緑で、合っているように見えた)。
- 吸着していない点で合わせた時の注意(「線の端や交点に吸い付いていない点で合わせています」)は、確定後も縮尺の表示の下に出し続け、保存後の文言にも添える。

### A5. 常設の「精度の目安」
- 1行目: A1 の分類の文。
- 2行目(縮尺が決まっている時): 「10m の長さで 約 ±○mm」= 床(軸平行) + 10000×相対誤差。標準縮尺を採用中なら「長さによらず 約 ±○mm」。
- 相対誤差が 0.05% を超える時は注意色。

## B. 吸着のルーペと選び直し

問題: 図面全体を画面幅に収めるので、A3・1/100 で画面1ピクセル = 実寸約33mm。通り芯の交点と壁の角(60mm隣)は2ピクセル差で、どれに吸い付いたか見えない。取り違えると縮尺が1.6%ずれる。

### B1. ルーペ
- 図面の上にカーソルがある間、カーソルの近くに拡大表示を出す(pickLayer の上に重ねる canvas。ポインタイベントは通す)。出すのは、クリックで点が取れる時だけ(縮尺を合わせている最中か、縮尺が決まった後。「縮尺を選ぶ」で縮尺が未設定のうちは出さない)。
- 大きさ 168×168px・角丸・細い枠・白地。位置はカーソルの右上に 24px 離す。端では反対側へ逃がす。
- 中身は **取り出した線データ**(geom)を拡大して描く(ラスタ画像の拡大ではない)。倍率は画面表示の 8 倍。線は濃い灰、吸着の候補点は小さな丸、いま吸い付く点はモード色(合わせ中=橙、確かめ中=緑)の輪と十字。吸い付いていない時は十字だけ。
- 線が多いページでも軽く動くこと: ページごとに格子の索引(一様グリッド)を一度だけ作り、ルーペの範囲の線だけ描く。描画は requestAnimationFrame で間引く。10万本で 1フレーム 8ms 以内が目標。
- タッチ操作ではカーソルが無いので、押している間だけ指の上側に出す。

### B2. あいまいな時の選び直し
- クリックした時、吸着範囲(10px)の中の候補点を集め、同じ点(0.01pt 以内)はまとめる。吸い付く点から **6px 以内に別の候補点がある** 時は、点を確定せずに選び直しの小窓を開く。
- 小窓: 図面の上に重ねる 320×320px。候補点どうしの最小間隔が画面で 44px 以上になる倍率(下限 8 倍・上限 96 倍)で、線と候補点を描く。候補点は大きめの丸(半径7px、当たり判定は半径22px)。見出し「近くに点が複数あります。合わせたい点を選んでください。」、右上に閉じる ×。Esc・小窓の外のクリックで取り消し。
- 点を選ぶと通常のクリックと同じ扱いで確定する(`snapped:true`)。
- 開閉は 120ms のフェード。閉じた後のフォーカスは実寸の入力欄(合わせ中で2点目の時)。

## C. 検証つきARC

- 円弧にする条件を「当てはめた円と、元のベジェ曲線上の点(1本あたり t=1/8 刻み)のずれが、用紙上 0.05mm(`FLAT_TOL`)以内」に統一する。満たさない区間は折れ線(今の `flatten`)。
- 小さい円が4本の円弧に割れる不具合を直す: 同じ円かどうかの判定の許容を、座標の刻みに合わせて広げる(中心・半径の差 ≤ max(0.1pt, r×0.005, 2q))。まとめた後は端点全部で最小二乗の当てはめをやり直し、上の「ずれ 0.05mm 以内」を全区間で確かめる。全周なら CIRCLE。
  - q は抽出の途中では未確定なので、曲線の出力を抽出の最後(q を推定した後)にまとめて行う形に直す。
- g ≥ 1mm の粗いPDFで円・円弧がある時は、注意書きの欄に「座標の粗いPDFのため、円の中心と半径は目安です」を出す。
