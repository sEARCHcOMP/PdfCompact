## ✨ できること

8モードを 1つの HTML に同梱:

| モード | 内容 |
|---|---|
| 🗜 **PDF軽量化** | 書類/写真切替、OCR、4品質プリセット、縮まない時は自動画像化 |
| 🖼 **画像→PDF** | JPG / PNG / HEIC / BMP / TIFF / PDF 混在 |
| 🔄 **変換** | 形式変換、個別DL / ZIP |
| ✂️ **PDF編集** | ページ削除 / 並び替え / 回転 / 分割 / 抽出 |
| 📐 **PDFに画像配置** | JWWで作った枠 PDF に写真・図を流し込み |
| 🖤 **塗りつぶし(墨消し)** | 黒/背景色を選んで文字データごと物理消去する本物のリダクション、出力前に自動検証 |
| 📲 **スマホ転送** | QRコードを読むだけでスマホ⇔PCの双方向ファイル転送(オンライン専用) |
| 📐 **図面変換** | CADのPDF図面・メーカーのDXFを Jw_cad の図面ファイル(JWW)に変換(寸法1か所で実寸合わせ・線色1〜8/線種1〜8・精度の目安表示)。DXF でも保存可 |

## 📋 更新履歴

### v4.7.0 (2026-10-03) — Minor (📐 図面の寸法から縮尺を読み取る)
- **図面の寸法文字から縮尺を読む** (`readDimScale`): 数字だけの文字(100〜30000mm)を拾い、同じ向きで 30pt 以内にある線と対にして、最小二乗で分母を出す
  - 対応付けは2段階。1回目は**文字1つにつき最寄りの線1本だけ**で比をとって中央値(全部入れると短い補助線が混ざって中央値が壊れる)。2回目はその値で長さが 3% 以内に合う線だけを採る
  - 線は置き場所の升目(64pt)に仕分けてから探すので、線 6 万本でも 50ms 以内
- 使い道は3つ: ①縮尺未設定なら**ボタン1つで合わせる提案** ②設定済みなら**2%以上食い違う時だけ注意**+直すボタン ③合っていれば**答え合わせの数**(「寸法 49 か所と突き合わせ、95% が ±2.7mm 以内」)
- **誤警告を出さない関門**: 対になった寸法が 5 か所未満、または残差の中央値が「座標の刻み2つぶん」と「寸法の 1%」の大きいほうを超える時は、行ごと出さない。縮尺を自動で変えることはしない
- 実データ(1/50・600dpi の平面図 2 ページ)で確認: 1/50.01 と読み取り、寸法との差は中央値 0.74mm / 0.72mm、処理は 9.4ms / 5.4ms

### v4.6.1 (2026-09-21) — Patch (📐 縮尺の分母を直接打てるように)
- 「縮尺を選ぶ」の固定プルダウンを廃し、**分母を打ち込む数値入力**(`#p2dDen`)を本体にした。1/150・1/60 や小数(1/103.14)も指定できる
- プルダウンは「よく使う縮尺」への近道に降格(選んだ時点で確定)。**標準の縮尺の一覧(ルールRの判定に使う)は引き続きこの `<option>` 群が正**なので、ここに値を足すと採用判定が変わる点に注意
- 受け付けるのは 0.01〜100,000 の有限の数だけ。外れた値は理由を表示していまの縮尺を変えない
- 「縮尺を選ぶ」へ切り替えた時は、いまの縮尺の分母(`denOf`)を欄に入れる。未設定なら 1/100(プルダウンだけだった頃の既定と同じ手数)
- DXF の自動縮尺は、プルダウンへ `<option>` を挿し込むのをやめて入力欄に入れる(挿し込むと、次に PDF を開いた時の標準縮尺の一覧が汚れていた)

### v4.6.0 (2026-09-21) — Minor (📐 図面変換で DXF 入力に対応)
- **DXF を入力にできるように**: メーカー提供の DXF(3次元CAD由来)は SPLINE・ELLIPSE を含み、Jw_cad がそれを黙って飛ばすため外形が途切れる。`src/app/71-dxf-flatten.js` で円弧と細かい線に分解してから渡す
- 分解した部品を **PDF と同じ形の図面データ(geomFromPrims)に作り直して**画面に載せるので、青い線の表示・吸着・ルーペ・確かめる・保存が PDF の時と同じ部品のまま動く(DXF 専用の描画を持たない)
- DXF は実寸なので縮尺合わせの手順を出さない。A3 に収まる最小の分母を `chooseScale` で自動選択(図枠つきは余白3mm)。あとから選び直すと図面データごと作り直す(画面と保存の中身をずらさないため)
- 元の図面のレイヤ名をそのまま Jw_cad のレイヤへ。JWW は `primsDoc` から直接組み立て、DXF 保存は分解し直した `flatDxfBytes` をそのまま出す(色の割り当てに合わせて `keepColors` を切り替える)
- 「精度の目安」は DXF 用の文に切り替わる(線の位置の読み取り誤差は無く、残るのは曲線の置き換え分だけ)
- **手元の Python 版(実機合格済み)と実データで突き合わせ済み**: メーカーDXF 1本で 149,304 バイト中 **5 バイトだけ**の差(すべて sin/cos の最後の1ビット、図寸で 1e-15mm 未満)。図形数・線色・線種・レイヤ・用紙・縮尺は完全一致
- 読み込みは 1MB・図形2万個のメーカーDXFで 0.2〜0.4 秒。バイナリ DXF・図形の無いファイルは理由を付けて断る

### v4.5.0 (2026-09-21) — Minor (📐 図面変換 PDF→JWW / DXF)
- **新タブ「図面変換」**: CAD出力のベクタPDFから線・円・円弧・文字を取り出し、Jw_cad の図面ファイル(JWW・Ver700)または DXF(R12・Shift-JIS・実寸mm)に変換
- **JWW 出力(第2段)**: Jw_cad は DXF の色を必ず SXF対応拡張線色で読むため、線色ごとの画面色・印刷線幅の設定に乗らない。JWW を直接書いて**線色1〜8・線種1〜8**を持たせる(`src/app/72-jww-writer.js`・`73-prims-to-jww.js`。手元の Python 版からの移植で、同じ入力なら Python 版と1バイト一致。答え合わせは 手元の答え合わせスクリプト run-checks.js)
  - 座標は用紙上のmm(図寸)をそのまま書き、縮尺はヘッダにだけ入れる(`scale:1` + `headerScale:分母`)。標準縮尺を採用した時・プルダウンで選んだ時は分母をその値ちょうどで書く(割り戻すと 99.99999… になる)
  - 用紙は、ページがそのまま入るいちばん小さい Jw_cad の用紙。**Jw_cad の用紙は横置きしかない**ので、縦向きのページは一回り大きい用紙になる(A4縦→A3)。図形の側には 1mm の余裕を見る(用紙選びの 0.5mm の大目に見る分だけはみ出すと、書き出し前の検査で止まるため)
  - レイヤは「線」「円」「文字」。線の色は「白い画面で見やすい色」(既定)と「元の図面に近い色」の2種類。文字は常に線色2
  - **ひな形**: 内蔵(自作標本のヘッダ。図面メモ・レイヤ名は空)+ 利用者が自分の .jww を登録すると IndexedDB に**ヘッダだけ**保存して上書き(図形・メモ・レイヤ名は取り込まない)。Ver700 以外は理由を付けて拒否
  - 書き出す前に必ず読み直して検査(読み残し0・件数一致・線色1〜8・線種1〜8・用紙からのはみ出し)。1つでも外れたら保存しない
- 縮尺は「既知寸法の2点クリック+実寸入力」が主役(線の端・線どうしの交点に吸着)。「用紙に合わせる」で縮んだPDFも正しく合う。縮尺プルダウンは補助。未設定では保存させない
- 検算表示(別の2点の実寸と誤差の目安)と、PDFの座標刻みから推定した「精度の目安」を表示
- **精度の考え方**: 誤差を「縮尺の誤差(長さに比例)」と「測る線の両端の丸め(長さに無関係の床)」に分け、前者をゼロに近づけ、後者は正直に見せる(仕様 docs/plans/pdf2dxf-stage1-spec.md、根拠 docs/plans/pdf2dxf-precision-design.md)
- **標準縮尺の確認・採用**: 寸法2点で測った縮尺が、標準縮尺(縮尺プルダウンと同じ集合)と測り方の誤差の範囲 max(1.5u, 0.03%) で一致したら、標準値ちょうどを採用(「測った値を使う」で戻せる)。寸法が短い(u > 0.15%)・吸着していない点が1つでもある(どれだけ長い寸法でも)・線の位置の細かさが分からないPDFでは採用せず、理由を表示。97%・99.5% に縮んだPDFを標準縮尺と取り違えない(許容を 2u 以上に緩めると誤採用が出るので緩めない)
- 座標の刻みの推定は、直線の端点だけで判定(曲線の端点が格子に乗らない Chromium 製PDFで「推定できません」になっていた)。「精度の目安」は「線の位置が実寸で約○mm きざみに記録されています」と「10m の長さで 約±○mm/長さによらず 約±○mm」の2行(画面では「1目盛り」と言わない)。合わせる寸法で縮尺の精度が実際に落ちる時だけ(線の位置のきざみ q が分かるPDFは u = q÷d > 0.05%、分からないPDFは用紙の長辺の15%未満)、その場で長い寸法を案内。mm の格子の候補(用紙上 0.1mm・0.01mm)は倍数へ広げない(5mm・10mm の切りのよい寸法で設計した細かいCADのPDFを「実寸で約 20mm きざみ」のように言っていた)
- 検算の誤差の目安 = 端点の床 + 長さ×縮尺の相対誤差。図面に書いてある寸法を入力すると一致・不一致を判定し、不一致からその寸法で合わせ直せる(「前の縮尺に戻す」で取り消せる。合わない時の案内は、まず点と寸法の確認を促す)。吸着していない点で合わせた注意は、確定後・保存後・ほかのページへ写した後も残す
- 第1段の検証で見つかった穴を修正: ①座標の細かさが分からないPDF(後から縮めたPDF・線の少ないPDF)では、検算で一致・不一致を言い切らず差だけを表示(正しい寸法の約半分が「合いません」になっていた。差が「長さの0.3%」と「300dpi相当の1目盛り」の大きいほうを超える時だけ不一致) ②座標の刻みの推定を外れ値に強く(差の2/3以上が乗るいちばん粗い刻みを採る多数決。プリンタ経由の図面に小数そのままの線が混ざると「十分に細かいPDF・±1mm未満」と言い切っていた。刻みの判定に使うのは、見えている線として描いたパスだけ。mm の格子の候補だけは従来どおり99%を要求) ③標準縮尺と一致しない時に「原寸で出力されたPDFではないようです」と言い切らない(1/150 などの原寸図面や点の取り違えでも同じ表示になるため、縮尺の行は事実だけにし、理由と次の一手を注意の行に出す) ④縮尺の欄と図面の上の操作の結果・エラーは、縮尺の欄の中に表示(保存ボタンの横=画面の外に出て、押しても無反応に見えていた)。2点が近すぎる時はその場で知らせて確定させない ⑤選び直しの小窓が、狭い窓・横向きの図面で下端を切られない(このタブの図面欄だけ overflow を visible に。代わりに、図面欄の幅が変わったら(取説を右に開閉した時も)図面を幅に収め直す) ⑥刻みを決められないPDFでも、線のかなりの部分(20%以上)が、アプリの知っている粗い格子(300〜2400dpi 等)に乗っていれば「十分に細かいPDF」とは言わない(候補に無い刻みの格子=後から縮めたPDFに、小数の細かい線が混ざった場合は、まだ見分けられない。残課題) ⑦吸着していない点(線の途中など)で合わせた時は、どれだけ長い寸法でも標準縮尺かどうかを判定しない(吸着なしの誤差を画面1ピクセルぶんと見込むだけでは手のずれを覆えず、用紙幅の3/4を超える寸法を線の途中のクリックで合わせると、0.5%縮んだPDFを1〜2割の確率で「1/100ちょうど」と取り違えた。採用時の「長さによらず ±4.2mm」と保存後の「誤差が大きい可能性があります」の食い違いも解消) ⑧選び直しの小窓の縦位置は、最後に必ず画面(ビューポート)で抑える(狭い窓で、用紙の上のほうだけが画面の下端に見えている時、小窓が画面の下へはみ出して選ぶ点が1つも見えなかった。この時は縮尺の欄の上に重ねて開く)。小窓の中では Tab が外へ抜けない ⑨文言: 「座標」を「線の位置」に言い換え/「短い寸法です」の注意に「このままでも合わせられます」を追加/一致しなかった時の例は測った値にいちばん近い標準縮尺(1/50 の図面に「1/100 など」と出さない)/写した先のページでは「クリックした2点」を確かめさせない/確かめ中は図面の上のラベルにも ± を表示/狭い幅で手順2の番号だけが1行に取り残されないように
- 画面確認で見つかった不具合を修正: ①画面の低い窓(1366×650 など)では、図面をクリックしている間、縮尺の欄が画面の上へ出ている。2点目を取った時は実寸の入力欄を、縮尺を変えた後(合わせる・合わせ直す・戻す・切り替える・選ぶ)は縮尺の行を、画面の外にある時だけ見える所へ動かす(共通の部品 bringIntoView。以前は、確定後に先頭に見える行が「測った値を使う」のリンクになり、いまの状態のように読めた)。合わせ中の図面の上のラベルに次の手順「実際の長さを入力して Enter」を添える ②確かめる欄は、入力の途中では判定しない(「3640」と打つ間の「3」「36」「364」で「合いません」と合わせ直しのボタンが出ては消え、欄の高さが 96px 跳ねていた)。判定は、入力が止まって約0.6秒・Enter・欄を離れた時。入力中は欄の高さを保つ
- 表示の見直し: 緑は「一致しました」の判定だけ(実寸の行はふつうの文字色、合わない時は図面の上のラベルも注意色)/標準縮尺と一致しなかった時・縮尺が未設定で図面をクリックした時・ZIPで保存しなかったページの文言(「3 ページ目は、縮尺が未設定のため保存していません。」)/指で操作する端末ではリンク・ボタン・小窓の × を 44px 以上に/PDFを読み込んだら操作欄を画面の上端へ/ルーペは点が取れる時だけ(「縮尺を選ぶ」で未設定のうちは出さない)/「測った値を使う」のリンクに説明を付け、測った値が標準の縮尺と同じ表示になる時は出さない
- **吸着のルーペと選び直し**: カーソルのそばに、取り出した線データを8倍で描くルーペ(一様グリッドの索引で、線10万本でも1コマ8ms以内。タッチは指の上側に出し、指を離した時に点を取る)。吸い付く点の6px以内に別の候補点がある時は確定せず、拡大した小窓で選び直す(通り芯の交点と壁の角の取り違えで縮尺が1.6%ずれるのを防ぐ)
- 書式は Jw_cad 実機で確定: TABLES(LTYPE・LAYER)必須(無いと全線が補助線種)、DASHED→破線・CENTER→一点鎖線、色番号1〜6はそのまま
- 円弧は折れ線にせず CIRCLE/ARC で出力(Jw_cad で中心が取れる)。中心は端点の接線と最小二乗で求め、Chromium 製PDFで半径誤差0.05mm以内を実測
- **検証つきARC**: 当てはめた円が、元のベジェ曲線(1本あたり t=1/8 刻み)から用紙上0.05mm以内に収まる時だけ CIRCLE/ARC にし、外れる曲線は折れ線。600dpi 相当に丸めたPDFで小さい円が4本の円弧に割れる不具合を修正(同じ円の判定の許容を座標の刻みに合わせ、まとめた後に全区間で検証し直す)。円・円弧の確定は、刻みが分かる抽出の最後にまとめて行う(切り抜き・非表示レイヤは描いた時点の状態に従う)。線の位置が実寸1mm以上のきざみで記録された粗いPDFでは「円の中心と半径は目安」と表示
- 塗りつぶし・切り抜きは線にしない。用紙の外・切り抜きの外・非表示レイヤ(OCG)は出さず、注釈は画面に見えている位置に出す。スキャン画像のみのページは理由を表示して断る。複数ページはZIP保存(「全ページに使う」は同じ用紙サイズのページだけ)
- build.js に制御文字の混入ガードを追加(開発中、正規表現に NUL が混入して全機能が停止する事故をテストで検出したため)
- PDFが漢字を「部首用の別の文字コード」で記録している場合(Chromium+游ゴシック・メイリオ製のPDFで「文・戸・長・高・金・土・木」など約230字)も、元の字に戻して書き出す(JIS 全7,326字の往復で全数確認。Jw_cad 実機で「縦の文字」が「縦の?字」になって発覚)
